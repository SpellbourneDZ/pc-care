# SPE-62 — рабочий экран «Умная очистка»

## Поведение и граница

Экран использует read-only cleanup API SPE-61. «Найти мусор» в обзоре запускает тот же анализ. Состояние анализа и выбор живут в Shell: переход в другой раздел не сбрасывает задачу. Reload приложения не восстанавливает in-memory scan; durable operation recovery относится к SPE-63.

Flow: анализ → категории → ручной выбор/список файлов → backend OperationPlan → проверка перечня → завершение предпросмотра. Настоящая очистка ещё не подключена. Кнопка явно называется «Завершить предпросмотр», результат сообщает, что файлы не изменялись; клиент не вызывает execute_plan и не создаёт фиктивный OperationResult. Несимулированный план пока отвергается. Полный flow с реальным результатом операции завершается в SPE-63; этот AC не следует считать проверенным в SPE-62.

Категории и их описание берутся из закрытого Rust registry. GetCleanupRules теперь возвращает CleanupCatalog: rules, max_plan_items и fixture_mode. Это одно обновление контракта и всех существующих callers, типы сгенерированы Rust. Произвольные roots/пути не добавлены в IPC.

## Выбор и размеры

- Автоматически выбираются только Safe candidates, для которых registry также сообщает Safe. Review остаётся без отметки. Protected/недопущенные объекты недоступны для выбора.
- В truncated snapshot автоматический выбор полностью отключён. Другие ограничения показаны отдельно и не выдают результат за полный.
- До 500 файлов в одном плане, предел виден при достижении; для остальных нужен новый ручной выбор. Фильтры не снимают скрытый выбор, итог всегда включает весь выбранный набор.
- Различаются allocation и logical size. U64 проверяются и складываются через bigint; округление отображения не влияет на итог. Размер не назван гарантированно освобождаемым.
- Drawer и preview разбиты на страницы по 100 строк; API snapshot собирается страницами по 500, с проверкой scan/offset/total/дубликатов/source и пределом 10000.
- Пути только отображаются: bdi dir=ltr, перенос длинных имён, управляющие bidi-коды показаны явно. Они не являются разрешением на системное действие.
- Изменение подтверждённой ревизии настроек очищает эффективный выбор и требует нового scan. Ошибка настроек не позволяет начать анализ.

## Состояния и доступность

Есть начальное состояние, skeleton, реальный processed count с indeterminate progress, отмена после backend acknowledgement, нулевой результат, частичный/ограниченный результат, typed error и восстановление. Неизвестный total не превращается в выдуманный процент. Чтение task можно повторить; мутации автоматически не повторяются, timeout не считается подтверждением отмены.

Категории фильтруются по имени/наличию совпадающего пути и классу риска. Drawer позволяет найти конкретные файлы и просмотреть allocation/logical size/risk. Ограничения содержат причину, количество наблюдённых объектов/источников и первый пример пути; неперечисленные потомки пропущенной директории не подсчитаны.

Одна основная CTA на шаг: анализ → предпросмотр → завершение предпросмотра. Повторный анализ вторичен в результатах. Preview имеет срок 30 секунд от начала запроса: истёкший план нужно получить заново. Подтверждение повторно проверяет срок и ревизию. Отмена/закрытие восстанавливают focus; Ctrl+K/Ctrl+B не перехватывают управление внутри modal. В компактном диалоге содержимое прокручивается отдельно от постоянно видимых кнопок. Сохранены monochrome tokens, обе темы, видимый focus и reduced motion.

## Изолированная проверка

Browser IPC fixtures всегда сообщают fixture_mode=true; каждая страница, drawer и preview помечены как тестовые. В обычном браузере без Tauri анализ честно недоступен; offline desktop не зависит от сети.

В qa-fixtures сборке PC_CARE_FIXTURE_AGED=1 сдвигает только часы анализатора на 30 дней, после обязательной проверки UUID root внутри target/native-fixtures. Так искусственные недавно созданные .tmp/cache проходят возрастное правило без изменения системного времени или метаданных пользовательских файлов. Production эту переменную не читает. QA scan/profile/process state искусственные, не использовать QA EXE как релизный.

Unit tests проверяют точность u64, некорректные wire values, paging/provenance/cancellation, порядок progress, Safe/Review/Protected, сохранение выбора при навигации, stale settings, предел 500, поиск, typed failures и expiry. Browser scenarios проверяют 1280×720, 1920×1080, 720×520 и device scale 125/150%, offline, длинные пути и modal focus. Device scale в браузере не заменяет OS DPI matrix.

Native QA test создаёт новый UUID profile с Temp .tmp, HTTP-cache и защищённым Login Data.tmp, проходит настоящий Rust IPC до предпросмотра и сравнивает исходные bytes всех файлов. Production smoke не запускает scan пользовательских каталогов. Чистые Win10/11 VM, OS DPI matrix, реальное удаление и отмена удаления здесь не проверялись.
